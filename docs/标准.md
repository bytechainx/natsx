# natsx 标准

**crate**：`natsx` v0.1.4 · 依赖：`async-nats` 0.50、`tokio`、`thiserror`、`serde`、`serde_json`、`toml`、`tracing`、`url`、`bytes`、`futures-core`、`futures-util`

## 1. 定位

natsx 提供 NATS 适配器：Core NATS 发布/订阅 + JetStream 持久消费，带 TLS 策略、连接池化与结构化健康报告。零内部依赖的标准组件库，只依赖 crates.io 公开包；不实现 NATS 服务端、K/V·Object Store 高层封装或消息总线语义。

## 2. 配置治理

- `NatsConfig`：结构体 + `builder()` / `from_env()` / `from_toml()` + `validate()`，校验失败 fail-fast；`SCHEMA_VERSION = 1`。
- 环境变量规范前缀 `FOUNDATIONX_NATSX_*`，兼容 `FOUNDATIONX_NATS_*`（前者优先）；键名以 `config` 模块 `ENV_*` 常量为准。
- `password` / `token` / `nkey_seed` / `jwt` 禁止进入 TOML，只能经 env 或 builder 注入；`Debug` 一律脱敏（`***`），URL 内嵌 userinfo 同样脱敏。
- 队列有界：`subscription_capacity` / `client_capacity` 可配置，禁止无界缓冲。
- 超时必备：`connect_timeout` / `operation_timeout` 可配置且经 `validate_operation_timeout` 校验。
- `slow_consumer_timeout` 可选；缺省回退 `operation_timeout`；显式零值在 `validate()` 拒绝。环境键与 TOML 键以 `ENV_*` / 字段名为准，不在本页抄第二份字面量。
- `from_toml` 的错误消息**不得**回显 TOML 源码片段（出错行可能承载凭据）：只保留错误摘要、
  行号与字节区间。

## 3. TLS 策略（fail-closed）

- loopback 默认 `TlsPolicy::Prefer`；非 loopback 默认 `Require`。
- `validate()` 拒绝「非 loopback + 非 Require」组合；显式 `tls_policy` 优先于 `tls` 布尔开关。
- TLS 后端为 `ring`（async-nats 默认 feature 固定能力边界）；自定义 CA 经 `add_root_certificates` 注入，避免平台证书目录不可读时建连失败。

## 4. 连接与消费

- `NatsPool` 可克隆、`Send + Sync`；`connect` / `connect_from_env` / `new`。数据面含 `publish` / `publish_json`。`close` 立即关闭，`drain(timeout)` 优雅排空在途消息。
- JetStream 采用有限拉取（pull）消费：`JetStreamConsumer` 显式确认 `ack` / `nak` / `progress` / `term`，不自动 ack。
- subject / stream / consumer 名称经 `validation` 纯函数校验后才进入协议层。
- 健康与统计经 `health_check()` / `stats()` 返回结构化数据（`NatsHealth` / `NatsPoolStats`）。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

测试至少覆盖：公开 API 面与 `Send + Sync` 约束（`tests/api_surface.rs` + `src/lib.rs` 内 `public_api_surface`）、env 解析与前缀优先级（`tests/config_env.rs`）、连接失败路径（`tests/connect_failure.rs`）、校验纯函数与 TLS 策略判定（`tests/pure_functions.rs`）。全部离线，不依赖真实 NATS 服务。

基准：`benches/hot_path.rs`（`harness = false`，离线）覆盖配置构建 → validate → TLS 策略判定 → subject/stream 校验热路径；`cargo bench --bench hot_path -- --quick` 用于快速冒烟（`cargo test` 以 `--test` 模式运行时自动缩减为 10 次迭代）。
